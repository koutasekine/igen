- 公開先: https://igen.sapp.jp
- リポジトリ: igen
- 拡張子: `.igen`
- ライセンス: MIT(Copyright (c) 2026 Kouta Sekine)

## 1. 目的と前提

テーマに対してアイディアを出し(発散)、条件を書き足して 1 つの案にまとめる(収束)までを、1 つのテキストで行う単一 HTML のアプリ。

- 単一 HTML。外部ライブラリを使わず、データをどこにも送信しない。ネットワークなしで動く。
- テキストが正本。図・表からの編集もすべてテキストの書き換えに直し、テキストと一致しない状態を作らない。
- 発散と収束は 1 枚の HTML にまとめる。手法を通す順序は自由で、すべての手法を使う必要はない。
- 同時編集はしない。複数人で使うときは、1 人の画面を共有して埋めるか、各自が同じテーマで出したテキストを貼り合わせる(6 章)。
- タイマーは入れない。

## 2. 画面

画面の作りはプロジェクト計画(plan.sapp.jp)に合わせる。

### 2.1 配置

- 上の帯: 題「アイディア生成」、新規、開く、上書き保存、別名で保存、印刷 / PDF、ファイル名(保存していない変更があれば後ろに *)、保存の状態、ビューの選択欄、警告、例を読み込む、書き方。
- 左: テキスト欄(予約語・注の色付け)と、その下の診断の欄(エラー・警告の件数、項目ごとのまとめ、行をクリックで該当箇所を選ぶ、「修正依頼をコピー」)。
- 左右の境の分割バー。
- 右: ビュー(SVG の図・表)と、その下の編集パネル。
- 下の帯: 「アイディア生成 — データはどこにも送信されません。MIT License, Copyright (c) 2026 Kouta Sekine. S Apps」。
- 配色・字体・ボタンの形・ダイアログ・ドラッグ・アンド・ドロップの表示は、プロジェクト計画と同じ。

### 2.2 ビューの選択欄

発散と収束の見出しで分けて並べる。

| 区分 | ビュー |
|---|---|
| 発散 | アイディア一覧(共通入力)、マンダラート、蜂の巣ノート、マトリックス法、シックスハット、オズボーンのチェックリスト、SCAMPER、TRIZ の 40 原理、欠点列挙法、希望点列挙法、特性列挙法 |
| 収束 | KJ 法、セブンクロス、5W1H、マインドマップ、ストーリーボード、ポジショニング、既存調査、候補比較・評価、判断・消去法 |

### 2.3 ファイル

- 開く: `.igen` と `.txt`。ドラッグ・アンド・ドロップでも開ける。
- 上書き保存・別名で保存・Ctrl+S(Mac では ⌘S)・ブラウザ内の自動保存・開き直したときに続きから開く動作は、プロジェクト計画と同じ。
- 保存するときの名前の候補は、ファイル名がなければ `テーマ.igen`(ファイル名に使えない文字は `_`)。

### 2.4 図・表の保存

各図・各表の題の右に、図は「SVG」「PNG」「PDF」、表は「コピー」(タブ区切り)「SVG」「PNG」「PDF」を置く。「印刷 / PDF」は描けるビューを 1 ページに 1 つずつ印刷する。動作はプロジェクト計画と同じ。

### 2.5 そのほか

- 「書き方」のダイアログは、枠の外をクリックすると閉じる。
- 「例を読み込む」の例は、警告が出ないように書く。
- 「修正依頼をコピー」は、診断とテキストを生成 AI に渡す修正依頼の文としてコピーする。打った直後(解析を待つ間)に押したときは、待たずに解析し直してから作る。
- 編集パネルの入力欄に書きかけた文は、ビューを替えても、テキストが一時的にエラーになっても残す(書き込んだ欄は空にする)。

### 2.6 AI に相談

アイディア出しやまとめに詰まったときに、生成 AI を壁打ちの相手にするための相談の文をコピーする。

- 編集パネルの入力欄の下に、「困っていること(任意)」の入力欄と「AI に相談する文をコピー」のボタンを置く。どのビューでも(マトリックス・ポジショニングの図をまだ作っていなくても)使える。テキストにエラーがある間は使えない。
- 困っていることの欄の文は、ビューを替えても、テキストが一時的にエラーになっても残す。
- 打った直後(解析を待つ間)にボタンを押したときは、待たずに解析し直してから文を作る。
- 相談の文は「状況 → 困っていること → 頼みたいこと → 案を返すときの書き方」の順に作る。
- 状況には、テーマ、フェーズ(発散・収束)、ビューの手法とその説明、ビューのいまの状態、選んでいるアイディアを入れる。テキスト全体は入れない。
- ビューのいまの状態は、次のとおり。アイディアなどを並べるところは、行に並べるときも 1 行に並べるときも 80 件までにし、残りは件数だけ書く(選んでいるアイディアは 10 件まで)。
- 状況の中の、3.7 節で元として指せないアイディアには「(元には指せません)」と印を付ける(既存調査の関係する案の名前も同じ。見つからない名前には「(見つかりません)」と付ける)。

| ビュー | 入れる状態 |
|---|---|
| アイディア一覧 | (共通の内容だけ) |
| マンダラート | 盤面の中心、埋まっているマス、空きのマスの数(埋まっていれば、マスのアイディアを中心にした盤面なら置けること) |
| 蜂の巣ノート | シートの中心、広げる元の枠、シートにある枠 |
| マトリックス法 | 縦と横の項目、考えているマス、マスに書いたアイディア、まだ案のないマス |
| シックスハット・オズボーン・SCAMPER・TRIZ | 対象、考えている観点とその問い、観点ごとにすでに出ている案 |
| 欠点列挙法・希望点列挙法・特性列挙法 | 対象、挙げた項目とその改善案(案)、改善案を考えている項目(特性列挙法では挙げている特性の種類) |
| KJ 法 | グループ(上位・説明・中身)、グループに入っていないアイディア、グループの関係、全体のまとめ |
| セブンクロス | 分類の軸、分類ごとの重要度の並び、どの分類にも置いていないアイディア |
| 5W1H | 案ごとの 5W1H と、まだ書いていない項目(見送りの案は除く) |
| マインドマップ | 枝を伸ばす元、元のアイディアをたどった木 |
| ストーリーボード | 場面を考えている案、その場面、その案の 5W1H |
| ポジショニング | 図、2 つの軸、置いた案の位置、まだ置いていない案(見送りの案は除く) |
| 既存調査 | 調べたもの(URL・関係する案・違い)、まだ調べていない案(見送りの案は除く) |
| 候補比較・評価 | 必須の条件、評価の観点と重み、案ごとの評価と合計 |
| 判断・消去法 | 採用・代替・見送りの案と理由、まだ判断していない案 |

- 発散のビューでは、重ならないように、テキスト全体にあるアイディアの名前も並べる。
- 困っていることは、各行の頭に `> ` を付けた引用として入れる(``` や `## ` を書いても、文の区切りを崩さない)。空なら、状況から詰まっていそうなところを考えるよう頼む。
- 頼みたいこと: 発散のビューでは、発想を広げる問いかけ(3 つほど)と案の候補(5 つほど)。収束のビューでは、まとめ方・判断の観点の提案(決めるのは利用者で、問い返しながら進める)。どちらも、問い返してよいと書く。
- 案を返すときの書き方: 案は、そのままテキストの最後に貼れる記法で書き、コードブロックで囲んで会話の文と分ける。`by: 生成 AI` と、ビューに合った `from:` を付ける(例: SCAMPER なら `from: scamper 観点` と対象の `from:`、マンダラートなら `from: mandala` と盤面の中心の `from:`、収束のビューなら手法名の `from:`)。元として書くのは、3.7 節で元として指せるアイディアだけにし、「元には指せません」と印のある案は from: に書かないよう伝える。中心・対象・広げる元・伸ばす元・改善案を考える項目が元として指せないときは、状況にその旨を書き、その from: をテンプレートに入れない(改善案を考える項目なら、項目を挙げる書き方にする)。名前の制限(3.7 節)と、5W1H・判断・評価を推測で埋めないことも書く。
- マトリックス法で、例にする組み合わせのマスがない(マトリックスがない、縦か横の項目がない)ときは、貼るとエラーになるのでテンプレートを出さず、先に縦の項目と横の項目を一緒に考えるよう頼む。

## 3. テキスト記法

### 3.1 行の種類

| 行 | 書き方 | 字下げ |
|---|---|---|
| 共通項目 | `theme: 値`、`author: 値`、`summary: 値` | しない |
| アイディア | `- 名前` | しない |
| グループ | `group: 名前` | しない |
| マトリックス | `matrix: 名前` | しない |
| セブンクロスの分類の軸 | `sevencross: 軸の名前` | しない |
| 評価の観点 | `criterion: 名前` | しない |
| 必須の条件 | `must: 名前` | しない |
| ポジショニングの図 | `positioning: 名前` | しない |
| 既存調査で調べたもの | `research: 名前` | しない |
| 属性 | `予約語: 値` | 直前のアイディア・グループなどの行より深く |
| 注 | `//` から行末まで(行頭か空白・タブの直後の `//` だけ) | — |
| 空行 | — | — |

- 予約語はアルファベットで書く。
- 字下げは半角の空白かタブ。属性の行の字下げの深さはそろっていなくてよい。
- アイディアの下に `- ` の行を字下げして書くことはできない(親子は `from:` で表す)。
- 次は構文エラーにする: 見出し(`#`)、番号付きのリスト、`* ` `+ ` のリスト、コードブロック(```` ``` ````)、字下げや `-` の後ろの全角空白(`- ` の後ろに半角の空白を挟んだ全角空白も含む)、上の表に当てはまらない行(説明の文など)。
- 名前と値の前後の空白(半角の空白・タブ・全角空白・ノーブレークスペース)は除く。名前と値の途中の全角空白はそのまま残す。
- `from:` の手法名と観点の間は、半角の空白・タブ・全角空白・ノーブレークスペースのどれで区切ってもよい。
- テキストのどこにある BOM(U+FEFF)も読むときに除く。画面のテキスト欄に貼り付けたときも、BOM と CR を除いて入れる。

### 3.2 共通項目

| 予約語 | 意味 |
|---|---|
| `theme:` | テーマ |
| `author:` | 画面からアイディアを足すときに `by:` に入れる名前 |
| `summary:` | 全体のまとめの文(KJ 法の文章化)。何回でも書け、書いた順につなげる |

- `theme:` と `author:` は、2 回以上書かれていれば先に書いた方を使う。`theme:` の値が違えば警告する(6 章)。
- 画面からテーマ(書いた人)を書き換えると、最初の `theme:`(`author:`)の行を書き換え、2 つ目からの行は消す。空にすると、すべての行を消す。
- `author:` は画面の入力の既定値にだけ使い、`by:` のないアイディアの書いた人にはしない。

### 3.3 アイディアの属性

| 予約語 | 回数 | 意味 |
|---|---|---|
| `by:` | 1 | 書いた人 |
| `from:` | 何回でも | 出所(3.4 節) |
| `group:` | 何回でも | 属するグループ(3.5 節) |
| `who:` | 1 | 誰のためか |
| `what:` | 1 | 何をする案か |
| `why:` | 1 | なぜ必要か |
| `when:` | 1 | いつ使うか |
| `where:` | 1 | どこで使うか |
| `how:` | 1 | どう実現するか |
| `rank:` | 何回でも | セブンクロスの分類と重要度(5.4 節) |
| `score:` | 何回でも | 候補比較・評価の評価(5.6 節) |
| `pos:` | 何回でも | ポジショニングの位置(5.7 節) |
| `scene:` | 何回でも | ストーリーボードの場面(5.8 節) |
| `decision:` | 1 | `adopt`(採用)・`backup`(代替)・`drop`(見送り) |
| `reason:` | 1 | 判断の理由 |
| `note:` | 1 | メモ |

回数が 1 の属性を同じアイディアに 2 回書くと構文エラーにする。

### 3.4 出所 `from:`

`from:` の値は次の 2 通り。

- 手法: `from: 手法名` または `from: 手法名 観点`
- 元のアイディア: `from: アイディアの名前`

値の最初の語が 3.6 節の手法名と一致すれば手法、そうでなければ元のアイディアとして読む。1 つのアイディアに両方を並べて書ける。

```
- 利用者の投稿で混雑を共有する
  by: 山田
  from: scamper 代用する
  from: 写真で登録するアプリ
```

これは「写真で登録するアプリ」に SCAMPER の「代用する」を当てて生まれた案、という意味になる。元のアイディアの `from:` がなければ、テーマに当てたものとする。

収束の途中で生まれた案も同じく、手法名(例: `from: kj`)と元のアイディアで出所を書く。

### 3.5 グループ

KJ 法のグループは、アイディアの `group:` で所属を書き、`group:` の行で見出しごとの情報を書く。

```
group: 探す手間を減らす
  note: 窓口に行かずに探したいという声が多い
  cause: 落とし物が持ち主に戻る

group: 探す手間を減らす::写真で探す
```

- 名前の `::` は上位グループとの区切り。`大::中::小` のように書く。
- アイディアは複数のグループに属してよい。
- `group:` の行がないグループも、アイディアの `group:` に書けばあるものとする。
- グループの行の属性: `note:`(見出しの説明・文章化)、`relate:`(関連)、`cause:`(因果。このグループが原因)、`oppose:`(対立)。関係の値は相手のグループの名前。`relate:`・`cause:`・`oppose:` は何回でも書ける。
- 同じ名前の `group:` の行が 2 回あれば、先に書いた方を使い、警告する。
- 画面からグループの名前を変えるとき、変えた後の名前(下位のグループを含む)が既存のグループと同じになるなら、変えない(行が重なり、関係が自分自身になるため)。既存のグループの下に入れる変更はできる。

### 3.6 手法名と観点

| 区分 | 手法 | 手法名 | 観点 |
|---|---|---|---|
| 発散 | 共通入力 | `direct` | なし |
| 発散 | マンダラート | `mandala` | なし |
| 発散 | 蜂の巣ノート | `honeycomb` | なし |
| 発散 | マトリックス法 | `matrix` | `縦の項目 × 横の項目` |
| 発散 | シックスハット | `sixhats` | 白・赤・黒・黄・緑・青 |
| 発散 | オズボーンのチェックリスト | `osborn` | 7.2 節の観点 |
| 発散 | SCAMPER | `scamper` | 7.3 節の観点 |
| 発散 | TRIZ の 40 原理 | `triz` | 1〜40 の番号 |
| 発散 | 欠点列挙法 | `defects` | 欠点・改善案 |
| 発散 | 希望点列挙法 | `wishes` | 希望点・案 |
| 発散 | 特性列挙法 | `attributes` | 名詞的・形容詞的・動詞的・改善案 |
| 収束 | KJ 法・親和図 | `kj` | なし |
| 収束 | セブンクロス | `sevencross` | なし |
| 収束 | 5W1H | `fivew1h` | なし |
| 収束 | マインドマップ | `mindmap` | なし |
| 収束 | ストーリーボード | `storyboard` | なし |
| 収束 | ポジショニング | `positioning` | なし |
| 収束 | 既存調査 | `research` | なし |
| 収束 | 候補比較・評価 | `compare` | なし |
| 収束 | 判断・消去法 | `eliminate` | なし |

観点のある手法で、観点が上の表にないものは構文エラーにする。観点のない手法に観点を書いても構文エラーにする。

### 3.7 アイディアの名前の参照

- `from:` の元のアイディアは名前で指す。同じ名前のアイディアが 2 つ以上あれば、先に書いた方を指し、警告する。
- 名前に予約語や記号の制限はない(属性は別の行に書くため)。ただし、最初の語(空白までの部分)が 3.6 節の手法名と同じ名前は、`from:` で元として指せない(手法として読む)ので、警告する。
- 画面からの書き換えでは、次の名前を作らない。
  - 最初の語が手法名の名前(足す・名前を変える)
  - ほかのアイディアと同じ名前(名前を変える)
  - 見つからない `from:`・`for:` が使っている名前(名前を変える。変えるとその参照がこの案につながるため)
- 画面で元・対象・中心として選べるのは、同じ名前がほかになく、最初の語が手法名でないアイディアだけにする(マンダラートの盤面の中心、蜂の巣ノートのシートの中心、シックスハット・オズボーン・SCAMPER・TRIZ・欠点列挙法・希望点列挙法・特性列挙法の対象、既存調査の関係する案)。図をクリックして選ぶ元(蜂の巣ノートの広げる元、マインドマップの伸ばす元、欠点列挙法・希望点列挙法・特性列挙法の改善案を考える項目)も同じで、指せないアイディアをクリックしたときは元にせず、そのことを知らせる。

## 4. 発散の手法

### 4.1 アイディア一覧(共通入力)

- 入力欄に書いて Enter で 1 件足す。足すと、テキストの最後に `- 名前`・`by: author の値`・`from: direct` が書き足され、入力欄は空になって次を書ける。
- 日本語入力の変換中の Enter では足さない。
- ビューは全アイディアのカードの一覧。

### 4.2 マンダラート

- 盤面は 3×3。中央は中心(テーマか、元のアイディア)、周りの 8 マスはその中心から出したアイディア。
- 中心がテーマの盤面のマスは `from: mandala` だけを書いたアイディア。中心がアイディア X の盤面のマスは `from: mandala` と `from: X` を書いたアイディア。マスの位置は書いた順。
- 周りのマスはそのまま収束の候補になる。
- マスをクリックして入力し、Enter で書き足す。マスのアイディアを中心にした盤面を開ける(2〜3 回くり返す使い方)。
- 盤面の周りの 8 マスに空きがあれば警告する。9 個目以降は盤面に置けないので警告する。

### 4.3 SCAMPER

- 対象はテーマか、選んだアイディア。
- 7 つの観点を問いとともに一度に並べ、観点ごとに入力して Enter で書き足す。足すと `from: scamper 観点` と、対象がアイディアなら `from: 対象の名前` が書き足される。

### 4.4 蜂の巣ノート

- 中心(テーマか、元のアイディア)の周りの六角形の枠に、隣へ隣へと広げて書く。
- 枠は `from: honeycomb` を書いたアイディア。元のアイディアの `from:` があれば、その枠の隣に広げた枠になる。元をたどって最初に蜂の巣ノートでなくなったアイディアが、シートの中心になる(なければテーマ)。
- 枠の位置はアプリが決める。元の枠の隣の空いた所に置き、隣が埋まっていれば、元の枠にいちばん近い空いた所に置く。元の枠とは線で結ぶ。
- 枠をクリックすると、その枠の隣に広げて書ける。周りの枠の数の検査はしない。

### 4.5 マトリックス法

- `matrix: 名前` の下に、縦の項目を `row:`、横の項目を `col:` で 1 行に 1 つずつ書く。項目に `×` は使えない。
- 組み合わせのマスに書いたアイディアは `from: matrix 縦の項目 × 横の項目`。
- 表のマスをクリックして書く。マトリックスを作る・項目を足す・使っていない項目を消すのも画面からできる。
- マトリックスが 2 つ以上あれば、アイディアは、その縦と横の項目を両方持つ最初のマトリックスのマスに置く。
- 2 つのマトリックスに同じ組み合わせ(同じ縦の項目と同じ横の項目)があれば、後のマトリックスに警告する(その組み合わせの案は先のマトリックスに置く)。画面からは、同じ組み合わせができる項目は足さない。

### 4.6 シックスハット・オズボーンのチェックリスト・TRIZ の 40 原理

SCAMPER(4.3 節)と同じ作り。観点と問いは 7 章のとおり。`from:` の観点は、シックスハットは色(`白` など)、オズボーンは観点の名前(`転用` など)、TRIZ は番号(`1`〜`40`)。

### 4.7 欠点列挙法・希望点列挙法・特性列挙法

- 先に項目を挙げ、項目ごとに改善案を出す。項目は、欠点列挙法は欠点、希望点列挙法は希望点、特性列挙法は名詞的特性(全体・部分・材料・製法)・形容詞的特性(色・性質・形・デザイン)・動詞的特性(メカニズム・機能)。
- 項目は `from: defects 欠点` などを書いたアイディア。対象(テーマかアイディア)の決め方は SCAMPER(4.3 節)と同じ。
- 改善案は `from: defects 改善案`(希望点列挙法は `from: wishes 案`)と、元の項目の `from:` を書いたアイディア。元の項目(最初の元のアイディア)が同じ手法の項目でなければ警告する。
- 図は左に項目、右にその項目の改善案。項目をクリックすると、その項目の改善案を書ける。項目も改善案も、ほかのアイディアと同じく収束の候補になる。

## 5. 収束の手法

### 5.1 KJ 法

- アイディアを選んで(複数可)グループにし、見出しを付ける。上位グループにまとめる。グループどうしに関連・因果・対立の線を引く。グループの説明と全体のまとめ(`summary:`)を書く。
- 所属を外しても、アイディアは消えない。

### 5.2 5W1H

- 案を行、who・what・why・when・where・how を列にした表。セルをクリックして編集する。
- 空欄は空欄のまま表示する。すべて埋めなくてよい。

### 5.3 判断・消去法

- 案ごとに `decision:`(採用・代替・見送り)と `reason:` を付ける。
- 見送っても、アイディアは消えない。
- 採用は 1 つだけ。代替は何個でもよい。

### 5.4 セブンクロス

- `sevencross: 分類の軸` の下に、分類を `class:` で 1 行に 1 つずつ書く。
- アイディアに `rank: 分類 重要度` を書く。重要度は 1〜7 の整数で、1 がいちばん重要。1 つのアイディアを複数の分類に置ける(分類ごとに 1 行)。
- 表は分類を列、重要度を行にする。アイディアを選んでから表のマスをクリックすると、その分類と重要度に置く。まだ置いていないアイディアは表の下に並べる。
- 分類の見出しをクリックすると、名前を変えられる(`rank:` の行も書き換える)。置いたアイディアのない分類は消せる。

### 5.5 マインドマップ

- テーマを中心に、各アイディアの最初の元のアイディア(`from:`)をたどった木を、左右に広げて描く。元のアイディアのないアイディアはテーマにつなぐ。2 つ目以降の元のアイディアとは点線で結ぶ。
- 枠(またはテーマ)をクリックすると、そこから枝を伸ばして書ける。足したアイディアは `from: mindmap` と、伸ばした元の `from:`。
- 元のアイディアをたどると自分に戻る(循環)ときは警告し、そのアイディアはテーマにつなぐ。

### 5.6 候補比較・評価

- 評価の観点は `criterion: 名前`(下に `weight:` で重み。省略は 1)、必須の条件は `must: 名前`。
- アイディアに `score: 観点 値` を書く。評価の観点の値は 1〜5 の整数(大きいほど良い)、必須の条件の値は `ok`(満たす)か `ng`(満たさない)。
- 表は見送り以外の案を行、必須の条件と評価の観点を列にする。合計は「重み × 評価」の和で、未評価があれば出さない。必須の条件が `ng` の案は灰色にする。
- セルをクリックして評価する。観点の見出しをクリックすると、名前と重みを変えられる(`score:` の行も書き換える)。評価のない観点は消せる。

### 5.7 ポジショニング

- `positioning: 名前` の下に、横の軸を `x: 左の言葉 .. 右の言葉`、縦の軸を `y: 下の言葉 .. 上の言葉` で書く。
- アイディアに `pos: 図の名前 横 縦` を書く。横と縦は -5〜5 の整数。1 つのアイディアを複数の図に置ける(図ごとに 1 行)。
- アイディアを選んでから図の中をクリックすると、いちばん近い目盛りに置く。まだ置いていないアイディアは図の下に並べる。同じ位置のアイディアは下にずらして描く。

### 5.8 ストーリーボード

- アイディアに `scene: 場面の文` を書く。書いた順に場面の番号を付け、左から右へ並べる。
- 画像は扱わない(テキストだけ)。
- 場面をクリックすると、文を直す・前後を入れ替える・消すができる。

### 5.9 既存調査

- `research: 調べたものの名前` の下に、`url:`、`for:`(関係する案の名前。何行でも)、`diff:`(自分の案との違い)、`note:` を書く。
- 表は調べたものごとに 1 行。行をクリックして編集する。案の名前を変えると、`for:` も書き換える。
- `for:` の案が見つからなければ警告する。同じ名前の案が 2 つ以上あれば、先に書いた方を指す。

## 6. 複数人での共有

- 各自が同じテーマでアイディアを出し、テキストをコピーして、受け取る側のテキスト欄に貼り付ける。取り込み専用のボタンは設けない。
- ファイル全体を貼ってよい。共通項目が重複しても構文エラーにしない。
- 同じ名前のアイディアは、書いた人が違っても同じでも、まとめずに両方残す。まとめるのは収束の作業で行う。

## 8. 診断

### 8.1 エラー

エラーがある間は、図を薄く表示し、図からの編集をしない。解析が途中で止まったとき(内部エラー)も、エラーと同じ扱いにし、診断の欄に知らせる。

- 3.1 節の構文エラー
- 知らない予約語、値のない属性
- 回数が 1 の属性の重複
- `decision:` の値が `adopt`・`backup`・`drop` 以外
- 観点が手法の観点にない、観点のない手法に観点がある
- `rank:` が「分類 1〜7」の形でない、`score:` の値が観点の種類に合わない、`weight:` が 0 より大きい数でない
- マトリックスの項目に `×` がある
- `pos:` が「図の名前 横 縦」(-5〜5 の整数)の形でない、`x:`・`y:` が「低い側 .. 高い側」の形でない

### 8.2 警告

- `theme:` の値が違う
- アイディアに `by:` がない
- アイディアに `from:` がない
- `from:` の元のアイディアが見つからない
- 同じ名前のアイディアがあり、`from:` の参照がどれか決まらない(先に書いた方を指す)
- すべての属性まで同じアイディアが 2 つ以上ある(`from:` は書いた順に、読んだ後の値で比べる。区切りの空白の違いは同じとみなす。ほかの属性は順に依らない)
- `adopt` が 2 つ以上ある
- マンダラートの盤面の周りの 8 マスに空きがある、9 個目以降がある
- 同じ名前の `group:` の行が 2 回ある
- グループの関係の相手が見つからない
- 元のアイディアをたどると循環している
- マトリックスにない組み合わせ、同じマトリックスの行が 2 回、同じ項目が 2 回
- `sevencross:` の行が 2 回、同じ分類が 2 回、`class:` にない分類の `rank:`、同じ分類の `rank:` が 2 回
- 同じ名前の観点(`criterion:`・`must:`)が 2 回、観点のない `score:`、同じ観点の `score:` が 2 回
- 改善案の元の項目(欠点・希望点・特性)がない
- 同じポジショニングの行が 2 回、図のない `pos:`、同じ図の `pos:` が 2 回
- 同じ既存調査の行が 2 回、`for:` の案が見つからない
- アイディアの名前の最初の語が手法名(3.7 節)
- 2 つのマトリックスに同じ組み合わせがある(4.5 節)
